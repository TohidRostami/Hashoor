# هاشور — فروشگاه اینترنتی پوشاک مردانه

فروشگاه اینترنتی «هاشور» ساخته‌شده با Next.js 16 (App Router)، Prisma، و Better Auth. این
راهنما مراحل راه‌اندازی محلی، اتصال دیتابیس و سرویس‌های بیرونی، و دیپلوی روی Vercel رو قدم‌به‌قدم
توضیح می‌ده.

## استک فنی

| بخش | تکنولوژی |
|---|---|
| فرانت‌اند و بک‌اند | Next.js 16 (App Router, Turbopack), TypeScript |
| دیتابیس | SQLite (محلی) / Turso (پروداکشن) از طریق Prisma ORM |
| احراز هویت | Better Auth (ایمیل/رمز + پیامک OTP) |
| UI | Tailwind CSS v4, shadcn/ui, Radix UI |
| انیمیشن | Motion |
| فرم و اعتبارسنجی | React Hook Form, Zod |
| نمودار پنل ادمین | Recharts |
| وضعیت سبد خرید | Zustand |

## ۱. راه‌اندازی محلی

```bash
npm install          # وابستگی‌ها را نصب و کلاینت Prisma را تولید می‌کند
cp .env.example .env  # اگر .env از قبل نساخته‌اید
```

سپس مقادیر زیر را در `.env` تنظیم کنید:

- `BETTER_AUTH_SECRET` — با دستور `openssl rand -base64 32` یک مقدار تصادفی بسازید.
- بقیه مقادیر برای اجرای محلی می‌توانند خالی بمانند (پایین‌تر توضیح داده شده).

سپس دیتابیس محلی را بسازید و پر کنید:

```bash
npm run db:push   # جدول‌ها را از prisma/schema.prisma می‌سازد
npm run db:seed   # دسته‌بندی‌ها و محصولات نمونه را وارد می‌کند
npm run dev       # اجرای سرور توسعه روی http://localhost:3000
```

### ساخت اولین حساب ادمین

از صفحه‌ی `/register` یک حساب کاربری عادی بسازید، سپس دسترسی ادمین را به آن بدهید:

```bash
npm run make-admin -- you@example.com
```

حالا با همان حساب وارد شوید و `/admin` در دسترس‌تان است.

## ۲. فایل تنظیمات محتوا

متن‌های ثابت رابط کاربری، رنگ‌های تم (که باید دقیقاً با `app/globals.css` هماهنگ بمانند)،
منوها و متن صفحه‌ی اصلی همگی در `content/site-config.json` هستند — برای تغییرشان نیازی به
دست‌زدن به کد نیست. محصولات، دسته‌بندی‌ها، سفارش‌ها، کدهای تخفیف و تنظیمات عملیاتی (مثل
فعال/غیرفعال‌بودن روش‌های ورود) از پنل ادمین (`/admin`) مدیریت می‌شوند.

## ۳. دیتابیس روی Vercel (Turso)

فایل SQLite به‌شکل فایلی روی Vercel کار نمی‌کند (فضای اجرا سرورلس است). راه‌حل: **Turso** —
دیتابیسی که دقیقاً بر پایه‌ی خود SQLite ساخته شده (fork متن‌باز libSQL) و از طریق شبکه در
دسترس است.

1. یک حساب رایگان در turso.tech بسازید (یا از طریق Vercel Marketplace، داخل داشبورد پروژه‌ی
   Vercel، مستقیماً Turso را نصب کنید).
2. یک دیتابیس جدید بسازید و `Database URL` و `Auth Token` را کپی کنید.
3. این دو مقدار را در Environment Variables پروژه‌ی Vercel قرار دهید:
   - `TURSO_DATABASE_URL`
   - `TURSO_AUTH_TOKEN`

کد به‌طور خودکار تشخیص می‌دهد: اگر `TURSO_DATABASE_URL` تنظیم شده باشد از Turso استفاده
می‌کند، وگرنه از فایل SQLite محلی (`lib/db.ts`).

4. بعد از اولین دیپلوی، جدول‌ها را روی Turso بسازید (یک‌بار، از سیستم خودتان):

```bash
TURSO_DATABASE_URL="..." TURSO_AUTH_TOKEN="..." npx prisma db push
```

سپس با همان روش بالا (`/register` + `make-admin`، این‌بار با متغیرهای Turso) اولین ادمین را
بسازید، یا مستقیم از `npx prisma studio` داده وارد کنید.

## ۴. دیپلوی روی Vercel

1. مخزن گیت پروژه را به Vercel وصل کنید (Import Project).
2. Environment Variables زیر را در تنظیمات پروژه وارد کنید (فهرست کامل در `.env.example`):
   - `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`
   - `BETTER_AUTH_SECRET` (یک مقدار جدید و امن برای پروداکشن)
   - `BETTER_AUTH_URL` و `NEXT_PUBLIC_SITE_URL` — آدرس نهایی سایت، مثل `https://hashor.ir`
   - در صورت آماده‌بودن: متغیرهای پیامک و درگاه پرداخت (بخش‌های ۵ و ۶)
3. Deploy بزنید. اسکریپت `build` به‌صورت خودکار `prisma generate` را هم اجرا می‌کند.
4. دامنه‌ی نهایی را در تنظیمات Vercel وصل کنید و مقدار `NEXT_PUBLIC_SITE_URL` /
   `BETTER_AUTH_URL` و `site.url` داخل `content/site-config.json` را با همان دامنه هماهنگ
   کنید (برای صحت sitemap، متادیتای سئو، و کوکی‌های ورود).

## ۵. اتصال سرویس پیامک واقعی

فعلاً کدهای OTP فقط در کنسول سرور لاگ می‌شوند (حالت توسعه). برای اتصال یک سرویس واقعی
(Kavenegar، Ghasedak، SMS.ir یا هر سرویس دیگر):

1. مقدار `SMS_PROVIDER_API_KEY` (و در صورت نیاز `SMS_PROVIDER_SENDER`) را در Environment
   Variables تنظیم کنید.
2. تابع `sendSms` در `lib/sms.ts` را با فراخوانی API همان سرویس تکمیل کنید — نمونه‌کد برای
   Kavenegar به‌صورت کامنت همان‌جا آماده است.

هیچ بخش دیگری از پروژه نیازی به تغییر ندارد.

## ۶. اتصال درگاه پرداخت واقعی

طبق درخواست، همه‌ی مراحل قبل از پرداخت (سبد خرید، فرم آدرس، بازبینی سفارش) و صفحه‌ی نمایش
نتیجه‌ی پرداخت آماده‌اند؛ فقط دو تابع در `lib/payment/index.ts` باید تکمیل شوند:

1. `initiatePayment` — درخواست پرداخت را به درگاه (زرین‌پال، زیبال، آی‌دی‌پی، ...) می‌فرستد و
   کاربر را به صفحه‌ی درگاه هدایت می‌کند. نمونه‌کد برای زرین‌پال به‌صورت کامنت آماده است.
2. `verifyPayment` — در `app/api/payment/callback/route.ts` فراخوانی می‌شود؛ همان مسیری که
   باید به‌عنوان callback URL در پنل درگاه ثبت کنید:
   `https://{دامنه شما}/api/payment/callback`

تا وقتی `PAYMENT_GATEWAY_MERCHANT_ID` خالی باشد، خرید از یک درگاه شبیه‌سازی‌شده
(`/checkout/payment-simulator`) عبور می‌کند تا کل مسیر خرید قابل تست باشد.

## ۷. اتصال Object Storage آروان‌کلاد (عکس‌ها)

عکس محصولات از طریق پنل ادمین (فرم محصول → «تصاویر محصول») مستقیماً روی
Object Storage آروان‌کلاد آپلود می‌شوند — سرویسی کاملاً سازگار با استاندارد S3،
پس همان AWS SDK معمولی (`@aws-sdk/client-s3`) برایش استفاده شده است.

1. وارد پنل آروان‌کلاد بشوید → بخش Object Storage → یک Bucket جدید بسازید
   (نام باید حداقل ۳ کاراکتر انگلیسی و یکتا باشد).
2. از همان بخش، یک Access Key و Secret Key بسازید.
3. مقادیر زیر را در `.env` (و در Environment Variables پروژه‌ی Vercel) قرار دهید:

```bash
ARVAN_ENDPOINT="https://s3.ir-thr-at1.arvanstorage.ir"   # یا آدرس منطقه‌ای دیگر
ARVAN_BUCKET="نام-باکت-شما"
ARVAN_ACCESS_KEY="..."
ARVAN_SECRET_KEY="..."
```

همین سه مقدار کافی است — آدرس عمومی هر عکس به‌طور خودکار از روی نام باکت و
endpoint ساخته می‌شود. اگر بعداً یک دامنه‌ی اختصاصی یا CDN جلوی باکت گذاشتید،
آن آدرس را در `ARVAN_PUBLIC_URL_BASE` قرار دهید تا لینک عکس‌ها از همان دامنه
ساخته شوند.

تا وقتی این متغیرها خالی باشند، تلاش برای آپلود عکس در پنل ادمین با یک پیام
فارسی روشن (نه خطای فنی مبهم) متوقف می‌شود؛ بقیه‌ی بخش‌های سایت بدون مشکل کار
می‌کنند و محصولات بدون عکس، از placeholder طراحی‌شده استفاده می‌کنند.

## ساختار پروژه

```
app/(shop)/          صفحات فروشگاه (خانه، محصولات، سبد خرید، چک‌اوت، حساب کاربری)
app/(auth)/          صفحات ورود و ثبت‌نام
app/admin/           پنل مدیریت (محافظت‌شده با نقش ADMIN)
app/api/             مسیرهای API (احراز هویت، callback پرداخت)
components/ui/       کامپوننت‌های پایه (shadcn/ui)
components/shared/   کامپوننت‌های مشترک فروشگاه (کارت محصول، لوگو، پلیس‌هولدر تصویر)
components/admin/    کامپوننت‌های پنل ادمین
lib/queries/         توابع خواندن داده از دیتابیس
lib/auth.ts          تنظیمات Better Auth
lib/payment/         نقطه‌ی اتصال درگاه پرداخت
lib/storage.ts       اتصال Object Storage آروان‌کلاد (آپلود عکس محصولات)
lib/sms.ts           نقطه‌ی اتصال سرویس پیامک
prisma/schema.prisma مدل کامل دیتابیس
content/site-config.json   متن‌ها و رنگ‌های قابل‌ویرایش سایت
```

## دستورهای مفید

```bash
npm run dev          # سرور توسعه
npm run build        # بیلد پروداکشن
npm run db:studio    # مشاهده/ویرایش دیتابیس با رابط گرافیکی Prisma Studio
npm run db:seed      # پر کردن دوباره‌ی دیتابیس با داده نمونه
npm run make-admin -- email@example.com   # ارتقای یک کاربر به ادمین
```
